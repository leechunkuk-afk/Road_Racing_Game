## 1. 사운드

### 정상 동작이 확인된 것
- 음악: `menu_cut.mp3`(메뉴) → `night_drive_cut.mp3`(주행, 72초) 크로스페이드가 실제로 동작.
  실주행 중 `Sound.musicCur.paused=false`, `volume 0.42`, id `mus_cruise`.
- 효과음: 충돌/부스트 계열 외부 파일(crash1, crash2, crash_glass, crash_break, boost_s/loop/e, eng_start) 22종 전부 로드.

### 결함 A — 엔진음이 외부 파일이 아니라 신디사이즈로만 재생되고 있었다
- 원인 1: `Sound.init()` 이 `Assets.load()` **이전에** 실행되어 `this.ext.eng1/2/3` 캐시가 전부 `null` 이었다.
- 원인 2: `Sound.engine()` 첫 줄이 `if (!this.eng) return;` 였고, `this.eng`(신디사이저)는 주행 중에만 만들어진다.
  외부 루프만 쓰려는 경로는 항상 조기에 리턴했다.
- 수정: 지연 참조(`Sound.rescan()` / `engEls()` / `sfxEl()`) + `main` 의 로드 완료 콜백에서 `Sound.rescan()` 호출,
  가드는 `if (!this.eng && !this.engExt) return;` 로 고쳤다.
- 추가 개선: rpm 대역 히스테리스(0.28 / 0.40 / 0.66 / 0.78)로 저/중/고 루프를 갈아타도록 변경(딸깍 방지),
  시동음 `eng_start` 재생, 메뉴 복귀·폐차 시 `stopEngine() + skid(0)`.
- 재측정(420프레임 수동 주행): 대역 사용 1=86 / 2=188 / 3=143 프레임, `paused=false`,
  volume 0.30~0.44, playbackRate 1.09~1.59. 신디사이즈 폴백(`Sound.eng`)은 미사용.

### 결함 B — 충돌음이 단일 샘플, 무게감 없음
- 수정: `crash_glass`(속도 55% 초과), `crash_break`(방호벽/건물/가로등 && 70% 초과) 레이어를 추가하고
  해당 오가 파일(`crash_bfh1_glass_breaking_03.ogg`, `crash_bfh1_breaking_01.ogg`)을 `CONFIG.assets.list` 에 등록.

### 참고(결함 아님)
- `jump` / `warn` / `pickup` / 미끄러짐(skid) 은 외부 파일 없이 WebAudio 합성으로 처리 중이다.
  OpenGameArt 에 해당 종류를 깔끔하게 대체할 소재가 마땅치 않아 의도적으로 유지했다.
- 미사용 에셋 27종(3.1MB)이 `assets/game/` 에 남아 있다(탑다운 차량 시트 12종, bg 사진 3종,
  칩튠 2종, 크래시 여분 2종, 아틀라스 xml). M3 교통차·메뉴 배경 후보로 보류했다.

## 2. 플레이어 차량 크기 (사용자 지적: "자동차가 너무 크다")

| 항목 | 수정 전 | 실측 기준 | 수정 후 |
|---|---|---|---|
| 화면에 그려지는 폭 | `W * 0.30` (마법 수치) | 접지선 투영 기준 0.108W(=1.95m) | `pxPerMeterAt(cy) * 1.95 * 1.25` → 0.152W (1280캔버스에서 195px) |
| 충돌 히트박스 합산 폭 | `0.34 * 2` (playerX 단위) = 6.12m | 1.95m | 1.76m (`hitGrace 0.90` 적용) |
| 점프대 승차 판정 폭 | 0.30 (하드코딩) | 실차폭 | `Physics.carHalfX()` 공유 |

-핵심: 크기가 **렌더·충돌·점프·HUD 에서 서로 다른 상수**를 쓰고 있었다. `CONFIG.car`
(`widthM 1.95`, `heroScale 1.25`, `hitGrace 0.90`, `halfX 0.108`) 를 단일 진실의 원천으로 만들고,
`Render.pxPerMeterAt(rowY)` 로 "접지선에서 1m 당 몇 픽셀"인지 계산해 차폭을 구하도록 바꿨다.
이 값은 소품(`drawSprite`)이 쓰는 투영식과 동일하므로 차와 사물 크기가 서로 맞는다.
- 재측정: `pxPerMeter = 80.0`(1280×720 캔버스, 접지선 0.80H), 차 그리기 폭 195px = 스크린 폭의 0.152,
도로 전 폭(18m)과 차폭(1.95m) 비율 = 0.108 로 실차 비율과 일치.

## 3. 코스 오브제 (사용자 지적: "오브제도 그렇고")

### 결함 C — Kenney 아틀라스 그림이 비율이 깨져 늘어져 보인다
- 원인: `Sprites.atlasDraw()` 가 `(w,h)` 에 그대로 끌어넣기(stretch). 프레임 아스펙트와 상자 아스펙트가 달라
  콘은 납작하게, 드럼통/나무는 늘어나 보인다.
- 수정: 프레임 비율 보존 + 접지선 고정(`baseY`)으로 변경. `(w,h)` 는 외접 상자로 취급.
- 실측 확인(화면에 그려진 상자 비율): `barrier 3.39` (원본 210×62 = 3.387), `cone 1.00` (45×44),
  `rock 1.22` (원본과 동일), `tirestack 1.00`, `tree 1.00`. 전부 원본 프레임 비율과 일치.

### 결함 D — `PROP_SIZE` 가 원본 그림 비율/실물 크기와 무관했다
- 수정(100유닛 = 1m 기준으로 실물화): `cone 0.70m`, `barrel 1.00m`, `tirestack 1.40m`, `barrier 4.30m×1.27m`,
  `rock 2.20m`, `tree 4.80m`, `streetlight 1.50m×9.50m`, `ramp 7.60m×2.10m`.
- 가드레일 경계도 실측에 맞춰 `railLimit 1.22 → 1.11` (노면 끝 1.0 + 차 절반폭 0.11) 로 좁혔다.

### 결함 E — 기름 패치가 코스에 단 한 개도 없었다
- 원인: `placeHazards()` 가 구역(`theme`)별 풀에서만 뽑아서, 테마 풀에 없는 유형은 통째로 빠졌다.
  (실측: `oil 0`)
- 수정: 유형별 최소 개수를 채운 **쿼터 주머니**(`quota: oil 4 / ice 5 / gravel 6 / wet 7`, 총 22) 를 섞어서 배정하고,
  테마 풀과 교집합이 있을 때 남은 개수가 적은 유형부터 꺼내게 했다. 개수도 14 → 22 로 증가.

### 결함 F — 점프 거리가 실제 물리의 약 2배로 표시됐다
- 원인: HUD 는 `p.y / 50`, 점프 토스트는 `vy² / 39200` 등 스케일 환산 상수가 물리와 무관하게 따로 흩어져 있었다.
- 수정: 월드 스케일 단일 기준 `CONFIG.unitPerMeter = 100` 과 물리 상수
  `CONFIG.physics.gravity = 392.4`(유닛/초², 100유닛=1m 기준으로 0.4g — 아케이드 공중감) 를 도입하고
  중력 적분·착지 판정(`landingHard`)·HUD·토스트가 모두 이 값을 쓰게 했다.
- 실측(최고속 정점 발사): 정점 4.44m, 체공 3.01s. 실주행 구간(118km/h 대)에서 정점 ≈2~3m.
- 실주행 노면 체감 확인: 기름 구간에서 `surface:'oil'`, `grip 0.17` 이 실측되고 횡방향 미끄러짐이 발생.

## 5. 미완/확인 필요 (이번 점검에서 손대지 않음)

- **AI 경쟁차·교통차 0대**: `Road.segments[].cars` 가 비어 있다 → M3 범위(계획서 순서대로).
- 상점/포인트/정비(M4) 미구현 → 현재 자유주행 시작 시 항상 정비된 상태로 시작.
- 차량 그래픽 자체(프록시 드로잉) 는 여전히 절차적이다. Blender 렌더 교체는 `docs/03_세이브포인트_차량렌더_comfyui.md` 의
  계획대로 진행 중이며, 교체 후에도 위 치수(`CONFIG.car`) 를 그대로 사용한다.
- 점프 체공 3초는 아케이드 기준으로 정한 값이다(0.4g). 실차감을 원하면 `CONFIG.physics.gravity` 를
  981(1.0g) 로 올리면 정점 1.8m / 체공 1.2s 가 되고, HUD 표시는 그대로 자동 재계산된다.
