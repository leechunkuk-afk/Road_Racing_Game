## 2. 차량 치수 (실측, 미터)

`car.json` 기준: **전장 4.300 / 전폭 1.976 / 전고 1.224**, 휠베이스 2.45, 트레드 1.69, 타이어 반지름 0.345,
접지점 z = 0(정렬 완료). 목표 대비 오차 0.000 / +0.026 / +0.004 (전폭 +26mm 는 휠 면이 10mm 돌출된 때문).

- 형상: 22개 superellipse 링을 X 축으로 로프트한 본체 + 9개 링의 캐빈(지붕=페인트, 옆면=유리),
  휠아치는 반원통 4개를 EXACT 불리언으로 잘라 만들었다.
- 소일부: 사이드스커트·디퓨저(핀 5)·범퍼 인서트·그릴·스플리터·리어 LED 스트립·리어 클러스터·DRL·
  덕테일 윙·번호판·미러, 타이어 4 + 휠면 4 + 허브 4 + 브레이크 캘리퍼 4 + 배기구 2.
- 총 8개 오브젝트 / 1848 정점. 게임 스프라이트 크기(약 160px)에서는 스포크·핸들 같은 세부 묘사가 보이지 않아 의도적으로 생략했다.
- 재질 슬롯 8: paint(메탈릭 + 코트 → 가로등 반사), trim(무광 검정), glass(짙은 틴트),
  lampR(발광 6.0), lampW(발광 2.2), plate, tire/rim, caliper.
  `PRIM_SOCKETS` 확인: Blender 5.2 의 Principled 소켓명은 `Base Color` / `Coat Weight` / `Coat Roughness`.
  `Base Color` 소켓에는 RGBA 4항을 넣어야 한다(3항이면 ValueError).

## 4. 스프라이트 프레임 (게임 연결 규격)

| 항목 | 값 |
|---|---|
| 위치·파일명 | `assets/game/car/<blue\|red\|white>/car_<ii>_<yyy>deg.png` (예: `car_07_035deg.png`) |
| 개수·용량 | 색 3 × yaw 16 = **48장, 3.62 MB**(장당 66~77 KB) |
| 프레임 크기 | 384×384 px, PNG RGBA(straight alpha · premultiply 없음) |
| 렌더 스케일 | `ortho_scale 4.8m` → **px_per_m = 80.0** (게임 접지선 축척 80px/m 과 동일) |
| yaw 목록 | 0~45(5° 간격) + 60/75/90/120/150/180 |
| 좌우 반전 | `mirror_negative_yaw: true` — 음수 yaw 는 반전 재사용(정합성은 5절) |
| 앵커 | `ground_x = 192`, `ground_y = 241` (차 중심의 **타이어 접지선**. bbox 아래변 262~264 아님) |
| yaw 규약 | 0 = 정후방. **+ = 차 코가 화면 왼쪽**(게임과 반대 → 6절) |

- 메타데이터는 `assets/car/car_frames.json`(파이프라인 전용) 에 기록되지만 **게임은 이 파일을 읽지 않는다**.
  `file://` 에서 fetch 가 차단되므로 필요한 값(px_per_m · 앵커 · yaw 목록 · 팔레트 · fx 좌표)은
  `CONFIG.car.sprites` 에 하드카피해 두었다(`src/01_config.js`).
- 에셋 id 는 `car_<색>_<ii>` (ii = yaw 목록 인덱스 00~15). `addCarSpriteAssets()` 가 48종을 만들며 전체 에셋은 70종(로드 실패 0).
  프레임이 한 장이라도 없으면 `carSpritesReady()` 가 false → 절차적 차체로 폴백한다.

## 5. 수치 검증

렌더 쪽(Blender):

- 정후방 프레임 ink = 160×119 px → 1.98m(전폭 실측과 일치). yaw 90 ink = 346px → 4.29m(전장 일치).
- 접지선 행은 yaw 와 무관하게 240.8 로 고정(직교 카메라라 거리·yaw 영향 없음).
- 미러 정합성: `-20°`/`-90°` 를 실제로 렌더해 `+20°`/`+90°` 의 좌우 반전과 비교 →
  rgb 평균절대오차 0.0026 / 0.0041, alpha 0.0002 / 0.0030 (0~1 스케일). 반전 재사용은 안전하다.
- 알파 형식: straight alpha("색 > alpha" 가 관측되므로 premultiply 아님). 발광 확인: 정후방에 빨강 계열, 측면에 흰 계열 픽셀 존재.

게임 쪽(브라우저 실측, `?v=fix5`):

- Assets 70/70 로드, 실패 0. 3색 모두 `carSpritesReady()` = true. FPS 60 (1280×720 로직, dpr 1.318 → 1687×949).
- 미러 유니트 테스트(`carSprite` 를 캔버스에 그리고 좌우 비교): rgb 평균절대오차 0.01, alpha 0.00,
  잉크 픽셀 수 24300 = 24300 (반전 전·후 동일).
- 프레임 선택·부호: `carFrameIdx(28.6°) = 6(30°)`, `carFrameIdx(-28.6°) = 6`. 후드−테일 중심 x 부호가
  −29°/−9° 에서 음수(코 왼쪽), +9°/+29°/+80° 에서 양수(코 오른쪽) → **게임 양수 yaw = 코 오른쪽** 규약이 프레임과 맞는다.
- fx 앵커가 실제 픽셀에 닿는지(프레임에서 색 샘플): `tailL@0 = [131,220] rgb 255,130,159`(테일램프),
  `tailC@0 = [192,223]`, `drlL@180 = [244,225] rgb 255,255,255`(전조), `exhL@0 = [166,252]`(범퍼 하부/배기구 주변).
- 화면 잉크 폭(ppm 80): yaw 0 = 160px, 30° = 278px, 90° = 349px. 접지선에서 잉크 꼭대기까지 95~101px.
- 오버레이 효과 강도(차량 상자 506×221 디바이스 픽셀, 꺼진 프레임과 켜진 프레임 비교):
  브레이크 등 → 밝아진 픽셀 7828개(최대 +62), 니트로 불꽃 → 15325개(최대 +211. 화면 워프 포함),
  손상(차체 100 → 20) → 어두워진 픽셀 3303개(최대 −158). 단일 픽셀 차이도 아니고 0 도 차이도 아니라 효과가 실제로 그려진다.
- 폴백: `Sprites._carPalOk['blue'] = false` 로 강제하자 절차적 `carRear` 가 1회 실행되어 차가 그려졌다(페이지 오류 0).

## 6. yaw 부호 규약 — 게임과 렌더는 좌우가 반대다

렌더는 yaw 0 = 정후방, `+` 는 카메라가 차 좌측(+Y)으로 돈 각도 → **화면에서 차 코가 왼쪽**.
게임은 `Physics.player.yaw > 0` 이 우핸들(코가 오른쪽)이고 기존 절차적 `Sprites.carRear` 도 같은 규약이다.

- 그래서 렌더의 `-yaw` 프레임은 게임에서 **양수** yaw 에 해당한다.
- 게임 코드 규칙: `frame = nearest(|yaw|)`, `flip = gameYaw > 0`. 프레임은 `|yaw|` 로 고르고
  게임 yaw 가 양수일 때 `ctx.scale(-1,1)` 로 좌우 반전해 그린다(`src/04_sprites.js` 의 `carSprite`).

## 7. 게임 연결에서 지킨 값

| 항목 | 값 | 근거 |
|---|---|---|
| 화면 축척 | `ppm = Render.pxPerMeterAt(cy)` = **80.0** at `cy = 0.80H` | 렌더 `px_per_m` 과 1:1. 보정 계수 1.000 |
| 차 크기 | `CONFIG.car.heroScale = 1.00`(실물 그대로), 화면 차폭 156~160px | 사용자 선택(② 실물 그대로) |
| 앵커 | `anchorX 192`, `anchorY 241`(접지선) | 스플리터(bbox 아래변)는 접지선보다 22px 아래. bbox 를 쓰면 차가 떠 보인다 |
| 히트박스 | `hitGrace 0.90`, `halfX 0.108` = 1.95m × 100 / (2 × 900) | 렌더·충돌·HUD 가 같은 실측을 공유 |
| 효과 | 렌더 재생성 없이 캔버스 오버레이(그림자 · 브레이크 발광 · DRL(yaw > 75) · 니트로 불꽃 · 손상 스크래치) | `CONFIG.car.sprites.fx` 차체 좌표 + `Sprites.carProj` |
| 명암 | `ctx.filter = brightness(0.74 + lit × 0.30)` 으로 가로등 밝기에 반응. 미지원 브라우저는 `filterOK()` 로 건너뜀 | Chrome 실측 `filterOK` = true |

- 효과 앵커는 차 좌표(m, +X = 앞 / +Y = 좌 / +Z = 위)로 두고, `carProj()` 가 렌더와 같은 직교 카메라 수식
  (카메라 거리 9m · 피치 10° · 타깃 z 0.62) 으로 프레임 픽셀로 변환한다. 5절 실측으로 정확한 픽셀에 닿음을 확인했다.
- 보닛 뷰(`Save.data.cam === 'hood'`)는 차체가 거의 보이지 않으므로 절차적 `carHood` 를 그대로 쓴다.

## 8. 게임 안 동작 / UI

- 조작/설정 패널에 **차량 색** 3종 버튼(`#rowColors`, 선택 표시는 ●/○). 고르면 `Save.data.carColor` 에 저장되고 즉시 반영된다.
  API 는 `Game.carPalette()` / `Game.setCarColor(id)`. M4 차고(포인트 상점)가 완성되면 그 화면으로 옮긴다.
- 크레딧: 플레이어 차량 3D 모델과 yaw 스프라이트 48장은 자체 Blender 렌더(제3자 자산 아님)로 표기.
  Unlucky Studio 등 OpenGameArt 차량 스프라이트 표기는 AI·교통차(상단 뷰)용으로 남긴다.

## 9. 남은 것

1. 인게임 스크린샷은 촬영 완료(`car_*.jpg`, `car_inset_*.jpg`). 가로등 반사·화면 체감 같은 마지막 판단은 사용자 확인.
2. yaw 45→60→75 구간 간격이 넓다. 계단이 거칠게 느껴지면 50/55 프레임을 추가 렌더(색당 3장, 약 0.2MB).
3. AI·교통차가 같은 프레임을 재사용할지(플레이어가 쓰지 않는 색을 AI 가 쓰는 방식)는 M3 에서 결정.
4. 음악 커트를 3MB 이하로 줄이는 일은 사용자 결정 대기(`mus_race` 는 M3 전까지 미사용).
